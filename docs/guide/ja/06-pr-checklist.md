# 6. PR を出す前のチェックリスト

## まず `pnpm check` を実行する

```bash
pnpm check
```

すべてのチェックが通ることを確認します。

## 目視確認チェックリスト

- [ ] 対象の画面・機能が mock モードで正常に動く
- [ ] 読み込み中・エラー・空の状態が表示される
- [ ] スマートフォンサイズで画面が崩れていない
- [ ] Storybook の story が追加されている
- [ ] 関係のないファイルが変更されていない

## やってはいけないこと

これらの変更が含まれていると CI が失敗してマージできません。

| やってはいけないこと                                  | 理由                                     |
| ----------------------------------------------------- | ---------------------------------------- |
| `backend/rapid-go/` 内のファイルを編集する            | バックエンドは読み取り専用               |
| `packages/api-client/src/generated/` を手動で編集する | 自動生成ファイル。`pnpm api:sync` を使う |
| `.env.example` の項目を削除する                       | 他の開発者のセットアップが壊れる         |
| `eslint-disable` コメントを追加する                   | エラーの根本原因を隠す                   |
| `: any` の型を追加する                                | 型安全性が失われる                       |
| テストファイルを削除する                              | カバレッジが下がる                       |
| Storybook ファイルを削除する                          | UI の確認手段が失われる                  |
| CI ワークフローファイルを削除する                     | 安全チェックが失われる                   |

## PR を作成する

問題がなければ PR を作成します。AI に「PR を作成して」と伝えると自動でドラフトを作成します。

PR の説明には以下を含めると reviewer に伝わりやすくなります:

- 何を追加・変更したか
- 動作確認の方法
- スクリーンショット（UI 変更がある場合）
